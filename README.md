# Эффективный бизнес: чат-бот + мини-приложение в MAX

## Назначение решения

Решение предназначено для **владельцев и руководителей малого бизнеса с посменной работой** (общепит, розница, салоны, клининг, фитнес) и их **сотрудников**.

Продукт закрывает две связанные задачи:

1. **Управление задачами и сменами** — постановка задач, назначение на сотрудника или в общий пул, отслеживание сроков, веса и статуса выполнения.
2. **Внутренние коммуникации** — объявления для всей организации или выбранных сотрудников, подтверждение прочтения, статистика по получателям.

Решение состоит из двух частей:

- **Чат-бот в MAX** — для коротких действий: поставить задачу, взять задачу из пула, отметить выполнение, отправить объявление, посмотреть отчёт.
- **Мини-приложение в MAX** — для визуального планирования: владелец видит, кто перегружен, какие задачи «зависли», где пропущены смены.

**Ценность:** владелец видит загрузку сотрудников и не распределяет задачи вслепую; сотрудник получает задачи и уведомления там, где он уже общается.

**Ожидаемый эффект:**
- сокращение времени на распределение задач;
- снижение числа пропущенных смен;
- снижение числа «зависших» поручений без исполнителя;
- повышение доли прочитанных объявлений.

## Основной пользовательский сценарий

### Сценарий 1. Регистрация и создание организации (владелец)

1. Пользователь запускает бота командой `/start`.
2. Бот запрашивает имя, фамилию, телефон (через контакт MAX).
3. Пользователь выбирает «Создать организацию».
4. Вводит название, город, выбирает тип организации.
5. Бот создаёт организацию, назначает пользователя владельцем и выдаёт **код приглашения**.
6. Владелец получает главное меню с ролями: управление сотрудниками, задачи, объявления, отчёты, настройки организации.

### Сценарий 2. Присоединение сотрудника

1. Сотрудник запускает бота командой `/start`.
2. Выбирает «Устроиться в существующую».
3. Вводит код приглашения.
4. Бот добавляет его в организацию с ролью «Сотрудник».
5. Сотрудник получает меню с доступными ему действиями.

### Сценарий 3. Постановка задачи (владелец/админ)

1. Владелец открывает «Управление задачами» → «Создать задачу».
2. Вводит название, описание, выбирает исполнителя:
   - конкретный сотрудник;
   - роль в организации (несколько сотрудников);
   - в общий пул (свободная задача).
3. Выбирает тип: разовая или регулярная.
4. Для разовой: дедлайн, время начала (опционально), оценка в минутах, вес.
5. Для регулярной: дни недели, время появления, deadline offset, период действия.
6. Бот показывает черновик задачи, владелец подтверждает.
7. Исполнители получают уведомление в MAX.

### Сценарий 4. Работа сотрудника с задачами

1. Сотрудник открывает «Мои задачи».
2. Видит список с дедлайнами, весом и статусом.
3. Открывает задачу, нажимает «Начать» → «Завершить».
4. Бот фиксирует фактическое время старта и завершения.
5. Свободные задачи из пула можно взять в работу.

### Сценарий 5. Объявления

1. Владелец/админ открывает «Управление объявлениями» → «Создать».
2. Вводит заголовок и текст.
3. Выбирает получателей: все сотрудники или выбранные.
4. Бот создаёт объявление и ставит рассылку в очередь.
5. Сотрудники получают объявление с кнопкой «Прочитано».
6. Владелец видит статистику: всего / прочитано / не прочитано, а также списки читателей и нечитателей.

### Сценарий 6. Отчёты

Владелец/админ может выгрузить CSV:
- по сотрудникам;
- по задачам;
- по выполнению задач;
- по объявлениям за период.

Файл отправляется в чат; при невозможности — выводится текстом с ограничением длины.

### Сценарий 7. Мини-приложение (визуальное планирование)

Мини-приложение подключается к чат-боту и открывается из меню. В нём владелец видит:
- загрузку сотрудников;
- активные задачи и их сроки;
- «зависшие» поручения;
- пропущенные смены.

> В MVP мини-приложение может использовать тестовые/подготовленные данные. Это явно указано в разделе «Работа с данными».

## Состав и архитектура решения

### Компоненты

| Компонент | Назначение | Технологии |
|---|---|---|
| Чат-бот MAX | Основной сценарий, короткие действия | Python, maxapi, aiohttp |
| Мини-приложение MAX | Визуальное планирование | HTML, JavaScript, CSS, MAX Bridge, MAX UI (React) |
| База данных | Хранение пользователей, организаций, задач, объявлений | SQLAlchemy (SQLite/PostgreSQL) |
| Очередь рассылки | Асинхронная отправка объявлений | Внутренняя очередь (`mailing.queue`) |
| Отчёты | Формирование CSV | Python, `reports` |
| Docker | Воспроизводимый запуск | Docker, Docker Compose |
